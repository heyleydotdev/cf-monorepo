Resolve the `turbo` package from this file's directory or relevant workspace; in monorepos, it may not be visible from the repository root. Read `docs/README.md` inside that installed package first, then read the relevant pages from its `docs/` directory before changing Turborepo configuration or commands. Heed deprecation notices. These bundled docs match the installed package version and are available without network access.

# Agent Instructions

## Package Manager

**bun 1.4.2** (`bun.lock`). Never npm, yarn, or pnpm. Shared versions live in the root `workspaces.catalog`; reference them as `"catalog:"`.

## Commands

| Task                 | Command                                               |
| -------------------- | ----------------------------------------------------- |
| All tests            | `bun run test`                                        |
| One test file        | `cd apps/server && bunx vitest run test/i18n.spec.ts` |
| Lint one workspace   | `bunx turbo lint --filter=@acme/core`                 |
| Format one workspace | `bunx turbo format --filter=@acme/tanstack`           |
| Scope any task       | `bunx turbo <task> --filter=@acme/<pkg>`              |

Root tasks: `build`, `typecheck`, `lint`, `test`, `format`, `format:write`, `clean`, `typegen`, `generate`, `dev`.

## Verify Before Reporting

`bun run format` → `bun run typecheck` → `bun run test` → `bun run lint`. Turbo caches by task hash, so a green run may be replayed; add the file change and it re-executes.

## Traps

**Read "Things that will bite" in `README.md` first.** It covers the runners, prettier versions, the `~/*` alias halves, `dev.port`, secrets, and the `VITE_` prefix. The entries below are not in it.

- **`includeIgnoreFile` needs `gitignoreResolution: true`.** `@acme/eslint` lives in `tooling/eslint/`, so the default resolves root `.gitignore` patterns against that directory, matches nothing, and looks like it works.
- **`ViteTypeOptions.strictImportMetaEnv` is what makes env vars type-checked.** Without it vite types `import.meta.env` as `Record<string, any>`, a misspelling compiles, inlines as `undefined`, and `new URL("/api", undefined)` throws `Invalid URL` at module scope. Deleting that block from `src/env.d.ts` restores it silently.
- **Do not override `envPrefix` to avoid the `VITE_` prefix.** A custom prefix must be declared in vite's `envPrefix`, turbo's task `env`, and `ImportMetaEnv`. Miss one and it is a stale bundle or a type error.

## Key Conventions

- No package compiles: `types` and `default` both point at `src/*.ts`, no `dist`, no `build` script.
- A package published to npm is the exception. It then needs `@acme/tsconfig/compiled-package.json`, `build: tsc`, and `types` at `dist/*.d.ts`. Nothing here is published.
- `apps/tanstack/src/routeTree.gen.ts` is generated and gitignored. Regenerate with `bunx turbo generate-routes --filter=@acme/tanstack`. The task is cached with that file as its output, so `build`, `typecheck` and `lint` all get a fresh tree.
- `apps/server/worker-configuration.d.ts` is generated by `bun run typegen` and **is committed**, so a fresh clone typechecks against real bindings. Re-run typegen after touching `wrangler.jsonc` and commit the result.
- Both apps typecheck through project references, so `eslint.config.js` must list every referenced tsconfig in `parserOptions.project`, or eslint reports the file is in no project.
- `typecheck` waits on `typecheck-transit`, not `^typecheck`. The transit task keeps a package's typecheck hash honest when a dependency changes without serializing packages. Swapping it back makes every app wait on every dependency first.
- A new public env var needs an `ImportMetaEnv` entry in `apps/tanstack/src/env.d.ts` and nothing in `turbo.json`.
- The document title is `createTitle(page)` from `@acme/core`, which appends `appName`. A framework name belongs in an app's own files and never in `@acme/core` or `@acme/ui`, since both are shared by every app and would then lie about what a given app runs.
- Root files are formatted by the `//#format:root` task. A new root file type means a new glob in `turbo.json` and in both `format:root` scripts. The globs skip `bun.lock` and `.env.example` on purpose.
- `packages/api` exports `api` as a concrete const and `ApiType` as `typeof api`. A factory return type loses the route literal and the RPC client infers `unknown`.
- File and directory names are lowercase kebab-case, except names a tool dictates: `README.md`, `AGENTS.md`, `bun.lock`, `tsconfig.*.json`, `apps/tanstack/src/routes/__root.tsx`, `routeTree.gen.ts`.
