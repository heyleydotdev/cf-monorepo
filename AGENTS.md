# This is NOT the Turborepo you know

Turborepo configuration, task behavior, and CLI commands can vary between installed versions and may differ from your training data. Resolve the `turbo` package from this file's directory or relevant workspace; in monorepos, it may not be visible from the repository root. For example, run `node -p "require.resolve('turbo/package.json')"` from a workspace that depends on `turbo`.

Read `docs/README.md` inside that installed package first, then read the relevant pages from its `docs/` directory before changing Turborepo configuration or commands. Heed deprecation notices. These bundled docs match the installed package version and are available without network access.

This block is written and re-added by `turbo` before repository-scoped commands when an AI agent is detected. In the Turborepo source repository, its template is defined in `crates/turborepo-cli/src/cli/agent_guidance.rs`. Set `"agentGuidance": false` in the root `turbo.json` or `turbo.jsonc` to opt out; this does not remove an existing block. Keep the block committed with your work to avoid an uncommitted change on the next agent invocation.

# Agent Instructions

## Package Manager

**bun 1.4.2** (`bun.lock`). Never npm, yarn, or pnpm. Shared dependency versions live in the root `package.json` `workspaces.catalog`; reference them as `"catalog:"`.

## Commands

| Task                 | Command                                               |
| -------------------- | ----------------------------------------------------- |
| All tests            | `bun run test`                                        |
| One test file        | `cd apps/server && bunx vitest run test/i18n.spec.ts` |
| Lint one workspace   | `bunx turbo lint --filter=@acme/core`                 |
| Format one workspace | `bunx turbo format --filter=@acme/tanstack`           |
| Scope any task       | `bunx turbo <task> --filter=@acme/<pkg>`              |

Root tasks: `build`, `typecheck`, `lint`, `test`, `format`, `format:write`, `clean`, `typegen`, `dev`.

## Verify Before Reporting

Run `bun run format` → `bun run typecheck` → `bun run test` → `bun run lint`. Turbo caches by task hash, so a green run may be replayed; add the file change and it re-executes.

## Key Conventions

- No package compiles. `types` and `default` both point at `src/*.ts`, there is no `dist`, and no package has a `build` script.
- A package published to npm is the exception. Then it needs `@acme/tsconfig/compiled-package.json`, a `build: tsc`, and `types` at `dist/*.d.ts`, because a consumer cannot read source it was not shipped. Nothing here is published, so nothing does this.
- Import specifiers are extensionless. Bundler resolution handles it, and a `.ts` or `.js` extension in an import is noise in a package whose source another package reads.
- `apps/tanstack/src/routeTree.gen.ts` is generated and gitignored. Regenerate via `bunx turbo generate-routes --filter=@acme/tanstack`.
- `apps/server/worker-configuration.d.ts` is generated by `bun run typegen` and **is committed**, so a fresh clone typechecks against real bindings. Re-run typegen after touching `wrangler.jsonc` and commit the result.
- `~/*` resolves to `src/*` in `apps/tanstack` via tsconfig `paths` **and** `resolve.tsconfigPaths` in `vite.config.ts`. Update both together.
- Secrets go through `wrangler secret put`, never `wrangler.jsonc`. Local dev reads root `.env` via `--env-file ../../.env`.
- `packages/api` exports `api` as a concrete const and `AppType` as `typeof api`. Do not make it a factory return type: the route path literal has to survive declaration emit or the RPC client infers `unknown`.
- File and directory names are lowercase kebab-case: `my-widget.tsx`, `api-client/`. Keep the names a tool dictates: `README.md`, `AGENTS.md`, `bun.lock`, `tsconfig.*.json`, `apps/tanstack/src/routes/__root.tsx`, generated `routeTree.gen.ts`.

## Sharp Edges

- **`bun run test`, never `bun test`.** `bun test` is Bun's runner and never reads `vitest.config.ts`, so the Workers pool and `cloudflare:test` imports do not exist and every spec fails to import.
- **prettier must stay on 3.5+.** Below that, `@ianvs/prettier-plugin-sort-imports` silently drops type arguments (`Promise<Response>` → `Promise`). `format` does not catch it; `typecheck` does.
- Every workspace that runs `prettier` needs it in its own devDependencies. Without it, the shell resolves a global install at an unpinned version.
- `bun run clean` runs `git clean -xdf` and fails outside a git checkout.
- `wrangler.jsonc` `dev.port` must be a number; the string form is rejected by `wrangler types`.
